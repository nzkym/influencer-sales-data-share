# 네이버 건강관련 전체 트렌드 분석기

## 프로그램 개요
`naver_health_trend`(건강식품 전용)의 확장판.
건강식품 카테고리는 그 프로그램이 전담하므로 제외하고, **나머지 전체 카테고리를 훑어서**
건강기능식품·건강용품·실버용품·화장품 사업 확장 기회 키워드를 찾는다.

### 2026-07-03 아키텍처 전면 변경 — "카테고리로 미리 고르지 않고, 다 훑은 뒤 키워드로 고른다"
기존에는 "건강과 관련 있어 보이는 카테고리"를 사람이 미리 26개 정도로 골라서 그 안에서만
스크래핑했다. 문제는 카테고리 단위 사전 선별로는 `어린이아토피로션`처럼 예상 밖 카테고리
(출산/육아 > 스킨/바디용품 등)에서 갑자기 뜨는 기회 키워드를 놓친다는 점이었다.

그래서 다음처럼 바꿨다:
1. **scraper.py — 전체 스윕**: 건강식품 1개 카테고리만 제외하고, 실물 상품 카테고리 전체
   (9개 대분류, 203개 중분류 — 도서/면세점/여가·생활편의는 상품이 아니라서 제외)를
   순위 기준으로 훑어서 원본 키워드 후보 풀을 만든다. 여기서는 관련성을 따지지 않는다.
2. **keyword_filter.py — AI 관련성 필터**: 원본 후보(수천 개)를 Claude(Haiku)로
   "건강기능식품 사업 확장과 관련 있는가"만 키워드 단위로 분류해서 골라낸다.
   비용은 미미함(키워드 목록 분류라 토큰이 거의 안 듦).
3. **이후 파이프라인은 기존과 동일**: 필터를 통과한 키워드만 naver_api.py(트렌드 데이터)·
   keyword_volume.py(검색량)로 넘어가 분석·리포트가 생성된다. 이 순서 덕분에 데이터랩 API
   일일 한도(1,000회/키)를 걱정할 필요가 없다 — 수천 개가 아니라 필터 통과분만 조회하므로.

### 스윕 대상 카테고리 (건강식품 제외 전체)
정확한 목록은 `scraper.py`의 `SWEEP_CATEGORY_MAP` 참조 (실측: 2026-07-03).

| 대분류 | 중분류 수 |
|---|---|
| 패션의류 | 4 |
| 패션잡화 | 17 |
| 화장품/미용 | 13 |
| 디지털/가전 | 28 |
| 가구/인테리어 | 17 |
| 출산/육아 | 31 |
| 식품 (건강식품 제외) | 27 |
| 스포츠/레저 | 32 |
| 생활/건강 | 34 |
| **합계** | **203** |

- 제외: 도서(26)·면세점(7)·여가/생활편의(10) — 구조적으로 실물 상품 기회와 무관.
- `SILVER_PRIORITY_CATEGORIES`(생활/건강의 실버용품·의료용품·재활운동용품·안마용품·
  건강측정용품·당뇨관리용품)는 통합 점수 산정 시 1.5배 가중치 — 실버산업이 현재
  최우선 사업 확장 방향이라는 사용자 요청 반영.
- 카테고리 선택이 실패하면(이름 불일치 등) **그 카테고리는 완전히 건너뜀**. 예전에는 실패해도
  화면에 남은 엉뚱한 카테고리로 계속 스크래핑해서 무관 키워드가 섞였음 (버그, 수정 완료).

### 네이버 차단(레이트리밋/캡차) 감지 및 알림
203개 카테고리를 순차 스크래핑하다 보니 네이버가 일시 차단할 가능성이 실제로 있다. 감지되면
**텔레그램으로 즉시 알림**을 보내고 스윕을 중단(그때까지 모은 데이터로 리포트는 계속 생성)한다.
- 차단 페이지 텍스트(`자동입력 방지`, `비정상적인 접근` 등) 직접 감지
- 카테고리 선택은 성공했는데 결과가 0개인 경우가 `BLOCK_SUSPECT_STREAK`(6회) 연속되면
  이름 불일치가 아니라 차단으로 간주
- 알림 로직: `scraper.py`의 `_send_telegram_alert()`

### naver_health_trend와의 차이
- **건강식품 전용** → **건강식품 제외 전체 카테고리 스윕 + AI 필터**
- 스윕 단계는 순위만 수집(3개월+1개월 2개 기간). 정밀 트렌드 데이터는 필터 통과 후에만 조회.
- 스크래핑 시간이 훨씬 길어짐 (약 1.5시간 안팎, 아래 "주의사항" 참고)
- **매주 목요일** 자동 실행 (naver_health_trend는 화요일)

## 실행 방법

```bash
python main.py                        # 기본 실행 (카테고리당 상위 30개 순위 수집)
python main.py --top 20               # 카테고리당 상위 20개
python main.py --no-scrape            # 스크레이핑 없이 캐시된 키워드 사용
python main.py --keywords 레몬즙 헛개나무  # 키워드 직접 지정 (스윕+필터 건너뜀)
python main.py --no-chart             # 차트 생성 건너뜀
```

`--top`은 **카테고리당** 수집 개수일 뿐, 최종 분석 대상 개수를 미리 자르지 않는다.
(예전 버전은 `combined[:args.top]`으로 통합 상위 50개만 남겼는데, 그러면 여러 카테고리에
걸쳐 골고루 뜨는 인기 키워드에 밀려 특정 카테고리의 니치 기회 키워드가 통째로 유실됐다 —
버그, 수정 완료. 최종 개수는 AI 필터 통과 결과에 따라 달라진다.)

## 파일 구조

```
naver_trend about all health_건강식품외 건강전체/
├── main.py            # 메인 오케스트레이터 (naver_health_trend와 동일 구조)
├── scraper.py         # 전체 카테고리(건강식품 제외) 스윕 스크래퍼 + 차단 감지/알림
├── keyword_filter.py  # AI 관련성 필터 (Claude Haiku) ← 이 프로그램만의 핵심 단계
├── naver_api.py       # 네이버 데이터랩 API 클라이언트 (동일)
├── analyzer.py        # 트렌드 분석 (동일)
├── keyword_volume.py  # 검색량 조회 (동일)
├── reporter.py        # AI 브리핑 — 광범위 건강 시장 관점으로 프롬프트 수정
├── pdf_report.py      # PDF 리포트 (동일)
├── emailer.py         # 이메일 전송 (동일)
├── requirements.txt   # 패키지 목록 (동일)
├── 실행.bat           # 로컬 실행용
├── run.sh             # 리눅스/서버 실행용
├── setup_cloud.sh     # 클라우드 서버 초기 세팅 (목요일 cron 등록)
├── .env               # API 키 (Git 업로드 안 됨)
├── .env.example       # API 키 양식
└── 결과값/            # 생성된 보고서 저장
```

## 분석 흐름

```
1. scraper.py         → 9개 대분류 203개 중분류 × 2기간(3개월/1개월) 스윕
                        (건강식품 제외, 도서/면세점/여가서비스 제외, 차단 감지 시 텔레그램 알림+중단)
2. keyword_filter.py  → 원본 후보 키워드를 Claude Haiku로 관련성 분류 (건강/실버/뷰티 관점)
3. naver_api.py       → 필터 통과 키워드만 데이터랩 API로 정밀 트렌드 조회 (장기/단기 4종)
4. analyzer.py        → 트렌드 분석: 성장률·추세단계·기회점수
5. reporter.py        → 광범위 건강 시장 관점의 AI 브리핑 생성
6. pdf_report.py      → PDF 리포트 생성
7. 텔레그램           → PDF 자동 발송
```

## 주의사항

- 203개 카테고리를 순차 스크래핑하므로 **초기 실행 시 약 1.5시간** 소요 (기존 26개 큐레이션
  버전 대비 대폭 증가 — 전체 스윕으로 바꾼 트레이드오프)
- 같은 IP로 장시간 연속 접속하다 보니 네이버 차단 리스크가 실제로 있음 — 감지 시 텔레그램
  알림 오고 스윕이 중단되며, 그때까지 모은 데이터로 리포트가 생성됨. 알림 오면 다음 실행은
  시간을 두고(또는 IP가 바뀐 후) 재시도할 것
- 캐시 유효 기간: 24시간 (재실행 시 자동 재사용, `--no-scrape`)
- `naver_health_trend`와 동일 VM에서 실행 가능 (동일 .env 공유 불가 — 별도 .env 필요)
- AI 필터(keyword_filter.py) 비용은 미미하지만, 필터 통과 키워드 수가 너무 많아지면(수백 개
  이상) 이후 naver_api.py 트렌드 조회 단계에서 하루 API 한도(1,000회/키)에 걸릴 수 있음 —
  이 경우 `.env`에 `NAVER_CLIENT_ID_2` 등 키를 추가 등록해 자동 로테이션되게 할 것
